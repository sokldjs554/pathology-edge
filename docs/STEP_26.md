# 26단계: WSI 영상의 드래그·스크롤 이동

상태: **사용자 이동 조작 확인 대기**. 25단계에서 R1 후보 추적의 이동·번호·원 패치 ID 표시를 확인했다는 보고를 받았습니다. 이번에는 같은 WSI 화면의 이동 기능 한 가지를 두 입력 방식으로 확인합니다. 앞서 TNBC 화면에서 확인한 이동과 별도의 뷰어입니다.

## 같은 영상에서 확인할 순서

현재 확대된 R1 후보 추적 화면에서 오른쪽 영상 안에 커서를 둡니다. 결과 패널이나 오른쪽 아래 작은 전체 위치 지도 위가 아닌 조직 영상 위에서 조작합니다.

1. **클릭을 누른 채 조금 드래그**합니다. 양쪽 영상이 함께 이동하는지 봅니다.
2. 클릭을 놓고 **트랙패드 두 손가락을 위아래로 움직여 스크롤**합니다. ⌘/Ctrl을 누르거나 손가락을 벌리지 않습니다. 이때도 양쪽 영상이 함께 이동하는지 봅니다.

정상이라면 확대 배율을 유지하면서 영상과 그 위의 후보·패치 표시가 함께 움직입니다. 자연스러운 스크롤 설정에 따라 손가락과 영상의 이동 방향은 달라질 수 있습니다.

**`드래그: 정상 / 스크롤: 정상`처럼 각각의 결과를 알려 주세요.** 동작하지 않는 쪽이 있으면 한쪽 영상만 이동하는지, 확대되는지, 웹페이지가 스크롤되는지와 브라우저 이름을 적어 주세요.

화면을 닫았다면 [실제 WSI 탐색](https://pathology-edge-lab.ykh13571.chatgpt.site/wsi.html)에서 **R1 → 결과·출처 → 실제 중복 후보 한 쌍 추적**으로 같은 확대 화면을 엽니다. 새 코드·설치·터미널 실행은 없습니다.

## Codex 확인 범위

`dist/wsi.js`의 OpenSeadragon 마우스 설정, 일반 wheel 입력의 `panBy`, ⌘/Ctrl wheel 입력의 확대 분기, 양쪽 중심·배율 동기화 코드를 읽었습니다. `web-tests/wsi.spec.js`에 스크롤·드래그 후 중심 변화와 동기화를 확인하는 기존 검사가 있습니다. 이번에는 검사 정의를 읽었으며 새 브라우저 테스트를 실행하지 않았습니다.

사용자 결과는 답변 후 해당 R1 화면 범위로 기록합니다. 모든 ROI·배율·브라우저나 정량적인 배율 유지 검사를 수행한 것으로 확대하지 않습니다.
