# 25단계: WSI 후보가 나온 패치 추적

상태: **사용자 화면 확인 대기**. 24단계의 예측 변화와 정확도 개선 구분 설명을 확인했습니다. 이번에는 R1의 후보 한 쌍과 원 패치 출처를 화면에서 연결합니다. 새 코드·설치·추론은 없습니다.

## 직접 할 조작 하나

현재 WSI R1 화면의 오른쪽 **결과·출처**에서 **선택 ROI 처리 기록** 아래 **실제 중복 후보 한 쌍 추적 →** 버튼을 누릅니다. ‘선택한 경계의 예측 차이’를 보고 있다면 패널 안을 조금 위로 스크롤하면 버튼이 있습니다.

화면을 닫았다면 [실제 WSI 탐색](https://pathology-edge-lab.ykh13571.chatgpt.site/wsi.html)에서 왼쪽 **R1**을 먼저 선택합니다. 결과 패널이 닫혔다면 상단 **결과·출처**를 누릅니다.

예상 결과는 **중복 출처** 모드로 바뀌고 후보와 원 패치가 있는 위치로 이동하는 것입니다. 오른쪽 **후보 → 패치 → 병합**에는 다음 두 줄이 표시됩니다.

- **분홍 #1302 억제 → 청록 #1107 유지**
- **원 패치 ID: 144 → 128**

**해당 위치로 이동하고 이 후보 번호와 원 패치 ID가 보이는지** 알려 주세요. 다른 값이라면 ROI 이름과 실제 번호를 보내 주세요. 다른 후보나 ROI까지 확인할 필요는 없습니다.

## 저장 기록 근거

이 모드는 같은 겹침 추론에서 나온 후보의 병합 전·후를 비교합니다. 픽셀 마스크는 양쪽이 같은 겹침 출력입니다. 앞서 본 무겹침·겹침 예측 비교와 구분합니다.

후보 화면 번호는 저장 raw 인덱스1301·1106에1을 더한 값입니다. 원 패치 ID는 저장된144·128을 그대로 표시합니다. 억제 후보의 패치 원점은 level-0 `(5888, 21184)`, 유지 후보의 패치 원점은 `(5888, 21120)`입니다. 두 후보의 native 상자는 `[5897, 21214, 5908, 21231)`로 같지만 서로 다른 겹침 패치에서 나왔습니다. 이 출처 대응이 실제 같은 핵이라는 정답 판정을 대신하지는 않습니다.

Codex는 `dist/wsi.json`의 R1 후보·유지 목록·억제 대응·패치 목록을 `artifacts/wsi/R1_overlap.json`과 대조했습니다. 이번 한 쌍의 유지/억제 포함 여부, IoU·거리·조건과 원본 좌표도 확인했습니다. 좌표 검산에 사용자 작성 함수를 Codex가 별도로 호출했으며, JavaScript 뷰어에서 Python을 실행한 것은 아닙니다.

화면 버튼·시야 맞춤·출처 표시 코드와 기존 WSI 테스트 정의를 읽었습니다. 이번에 NMS 재실행·새 브라우저 검사·모델 추론·정답 대조는 수행하지 않았습니다. 사용자 화면 확인은 답변을 받은 뒤 기록합니다.
