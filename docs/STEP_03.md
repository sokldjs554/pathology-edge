# 3단계: 중복 규칙을 바꾸기 전에 반대 오류 검토

상태: **사용자 해석 확인 완료** (2026-11-09, Asia/Seoul). 2단계의 반례 해석·테스트 본문·`1 passed in 0.01s` 보고를 확인했습니다.
사용자는 IoU 조건이 거짓이어서 AND가 성립하지 않고, 후보2개가 남아 실제 핵1개보다1개 과대 집계된다고 설명했습니다. 정확한 해석입니다. [검토 기록](../artifacts/learning/step03-review.json).

## 검토할 이유

2단계에서는 서로 다른 핵이 하나로 억제되는 과소 집계를 재현했습니다.
규칙을 바꾸기 전에는 같은 핵의 중복 후보를 남기는 경우도 함께 살펴봐야 합니다.
이 단계는 `src/pathology_edge/merge.py::deduplicate`의 정책을 판단하는 연습입니다. 실제 모델·저장 결과는 변경하지 않았습니다.

## 새로운 합성 상황

이번에는 **실제로 하나인 핵이 서로 다른 패치의 예측에서 두 조각으로 나뉘었다고 가정**합니다.
두 후보의 상자 IoU는0, 원본 좌표에서 중심 거리는6px입니다.
이는 실제 WSI의 새 정답이나 관찰 결과가 아니라, 규칙의 한계를 따져 보는 교육용 가정입니다.

현재 조건:

```text
IoU >= 0.3 OR 중심 거리 <= 8px
```

검토할 변경안:

```text
IoU >= 0.3 AND 중심 거리 <= 8px
```

## 확인한 질문과 설명

**OR를 AND로 바꾸면 이 사례에서 후보가 몇 개 남고, 실제 핵1개에 비해 어떤 집계 오류가 생길까요?**

위 질문에 대한 사용자 설명을 확인했습니다. 변경안은 구현하거나 채택하지 않았습니다.
이 합성 사례의 설명만으로 전체 데이터에서의 성능이나 임계값의 적절성을 판정하지 않습니다.
