# 19단계: 처리 시간의 측정 범위 확인

상태: **2026-11-09 사용자 처리 시간 해석 확인 완료**. CPU 처리 범위, 이미지별3회 중앙값에서7개 이미지 중앙값을 구하는 집계, 제외 항목과 웹페이지 로딩 시간의 차이를 설명했습니다. [답변·확인 범위](../artifacts/learning/step19-review.json). 아래는 완료한 과제의 참고이며, 다음은 [20단계 중복 후보 한 쌍 확인](STEP_20.md)입니다.

## 볼 곳과 질문 하나

[데모](https://pathology-edge-lab.ykh13571.chatgpt.site/) 오른쪽 **검토 결과 → 실험 탭**을 엽니다. `이미지 | 선택 후보 | 실험` 중 맨 오른쪽입니다. 패널이 닫혀 있다면 상단 **결과 패널**부터 누릅니다.

**전체 테스트 결과** 표의 **시간 중앙값** 행은 다음과 같아야 합니다.

| 방식 | 표시 시간 |
|---|---:|
| A 무겹침 | 57.2 ms |
| B 겹침·결합 | 309.3 ms |
| B/A 비율 | 5.41배 |

바로 아래 **처리 시간의 측정 조건**을 눌러 설명을 펼칩니다. 선택한11_1 이미지 하나의 시간이나 국소 경계 상자만의 시간과 구분합니다.

위 질문에 대한 사용자 설명을 확인했습니다. 답변은 측정 범위 해석으로 기록하며, 사용자가 실제로 조건 설명을 펼쳤다는 별도 보고나 새 측정을 실행했다는 근거로 확대하지 않습니다.

## 답변 검토

핵심 설명은 정확합니다. Codex는 NMS가 겹침 방식 B에서 실행되고 무겹침 방식 A에서는 생략된다는 점을 보완했습니다. ‘모델 처리 시간’이라고 줄여 말할 때도 신경망 순전파만이 아니라 위 전후 처리까지 포함한 파이프라인 시간임을 함께 설명하면 됩니다. NMS 적용 방식의 보완 설명을 사용자 기여로 소급하지 않습니다.

## 측정 기록 참고

방식별로 검증 이미지로 예열한 뒤, 테스트 이미지마다 CPU에서3회 실행한 중앙값을 구하고, 그7개 값의 중앙값을 다시 구했습니다.21회 시간을 한꺼번에 평균 낸 값이 아닙니다. 측정 환경은 AMD EPYC 9V74, Torch4스레드, CPU only입니다.

RGB 패치 추출·조직 검사·모델 순전파·확률 결합·후보 추출과 겹침 방식의 NMS가 측정 구간에 들어갑니다. 모델 로딩·디스크 I/O·정답 평가·브라우저 표시 시간은 제외합니다. 저장된512×512 PNG 실험의 기록이며 현재 사용자 Mac이나 WSI 전체의 처리 시간을 측정한 결과가 아닙니다.

경계 Dice 평균 개선은 앞서 확인한 `0.491793 → 0.527261`입니다. 시간 비율은 같은 실험의 처리 비용을 함께 읽기 위한 수치로, 품질 점수의 배수가 아닙니다.

## Codex 확인 범위

준비 당시 `artifacts/evaluation.json`의 원본3회 측정값에서14개 이미지별 중앙값과2개 방식별 중앙값을 재계산하고 `dist/results.json`과 대조했습니다. 집계 코드·화면 연결·측정 환경도 확인했습니다. 이번에는 답변을 검토하고 이전 근거의 원본 해시가 같은지 확인했습니다. 새 시간 측정·추론·브라우저 검사를 실행하지 않았습니다.
