# 20단계: 실제 중복 후보 한 쌍 확인

상태: **사용자 화면 확인 대기**. 19단계의 처리 시간 해석을 확인했습니다. 이번에는 앞서 합성 반례로 검토한 NMS가 실제 저장 결과에서 어떤 후보를 억제했는지 한 쌍만 살펴봅니다. 새 코드·설치·추론은 없습니다.

## 직접 확인할 사례 하나

1. [데모](https://pathology-edge-lab.ykh13571.chatgpt.site/) 왼쪽 위 예제 선택 목록에서 **TNBC 11_2**를 선택합니다.
2. 오른쪽 **검토 결과 → 선택 후보** 탭을 엽니다. `이미지 | 선택 후보 | 실험` 중 가운데입니다. 패널이 닫혔다면 상단 **결과 패널**을 먼저 누릅니다.
3. 패널 안을 아래로 스크롤해 **억제된 중복 후보 추적 → 첫 병합 사례로 이동**을 누릅니다.

화면이 **중복 병합** 모드로 바뀌고 해당 후보 위치로 확대됩니다. 이 모드의 왼쪽과 오른쪽은 모두 **겹침 방식 B의 병합 전·후**입니다. 무겹침 방식 A와 겹침 방식 B의 비교 화면과 구분합니다.

예상 표시는 **억제 raw #74 (patch 27) → 유지 raw #54 (patch 19)**입니다. 왼쪽에는 분홍 `raw #74 suppressed`와 파란 `raw #54 kept` 표시, 오른쪽에는 유지된 `raw #54 kept` 표시가 나옵니다. 두 후보의 상자 좌표가 같아 테두리는 겹쳐 보일 수 있습니다. 위·아래 번호 설명으로 구분합니다.

**버튼을 누르면 해당 위치로 이동하고, #74 억제 → #54 유지가 보이는지** 알려 주세요. 다르게 보이면 이미지 번호와 후보 번호를 그대로 보내 주세요. 다른 병합 쌍까지 확인할 필요는 없습니다.

## 저장 결과 근거와 범위

`11_2` 전체에는 병합 전116개 후보, 병합 후33개 후보, 억제83개가 저장되어 있습니다. 이번 한 쌍의 번호는 저장 배열의0부터 시작하는 인덱스73·53에1을 더해 화면에 표시한 값입니다. 실제 핵의 정답 번호가 아닙니다.

이번 후보의 bbox IoU는1이고 중심 거리는 부동소수점 오차 수준에서0입니다. 서로 다른 패치 출처이며, 둘 다 패치 가장자리에 닿지 않은 후보입니다. 유지 후보의 평균 예측값이 조금 높아 기존 NMS 순서에서 우선합니다. 이는 알고리즘이 남긴 대응 기록이며 두 후보가 같은 실제 핵이라는 임상적·객체별 정답 검증은 아닙니다. 앞서 검토했듯 다른 실제 핵을 잘못 억제할 가능성도 있는 규칙입니다.

Codex는 `artifacts/objects_overlap.json`과 UI 데이터를 대조하고 저장 후보에 NMS를 다시 적용해 유지33개·억제83개 전체와 첫 쌍이 일치함을 확인했습니다. 화면 이동·번호·그리기 코드와 기존 UI 테스트 정의도 읽었습니다. 이번에는 모델 추론이나 새 브라우저 검사를 실행하지 않았으며, 사용자 화면 확인은 대기 중입니다.
