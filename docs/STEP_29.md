# 29단계: IHC 모델에 주어진 입력과 예측 구분

상태: **사용자 해석 대기**. 28단계에서 정답·예측 분류 표시가 나온다는 보고를 받았습니다. 이번에는 현재 IHC 실험의 입력 조건을 해석합니다. 추가 화면 조작·코드·실행 명령은 없습니다.

## 질문 하나

**이 IHC 실험을 “세포 위치를 자동으로 찾아 종류까지 분류한 결과”라고 설명해도 될까요? 입력으로 주어진 정보와 모델이 예측한 것을 구분해 한두 문장으로 설명해 주세요.**

참고할 곳은 영상 위의 **정답 중심점이 입력됩니다** 안내와 오른쪽 **결과·출처 → 전체 테스트의 분류 성능** 아래의 평가 범위 설명입니다. 여기서 ‘중심점’은 세포의 위치이며, 정답 클래스와는 다른 정보입니다.

현재 화면의 네 클래스는 Ki67 양성/음성 종양 세포와 Ki67 양성/음성 비종양 세포입니다. 노란48px 사각형은 표시용 crop 범위입니다. 아래 소스·실험 기록은 참고자료이며 지금 코드를 수정하거나 테스트를 실행하는 과제는 아닙니다.

## Codex 확인 범위

`src/pathology_edge/ihc_baseline.py`에서 `read_points`가 반환한 중심 좌표를 `extract_features(rgb, centers)`에 전달하고 정답 클래스는 별도로 보관하는 흐름을 읽었습니다. 입력 특징을 추출할 때 정답 클래스 값을 특징으로 넣는 코드는 아닙니다.

`dist/ihc/results.json`과 원본 `artifacts/ihc/results.json`의 scope가 일치하고, 중심점 제공·검출/분할 평가 여부가 화면 설명과 같은지 대조했습니다. [28단계의 사례 대조](../artifacts/learning/step28-preparation.json) 입력 해시도 그대로입니다. 이번에 새 특징 추출·모델 추론·학습·브라우저 검사는 실행하지 않았습니다.

사용자 해석은 답변을 받은 뒤 기록합니다. 이번 확인으로 원영상 표시나 자동 검출 성능을 확인한 것으로 기록하지 않습니다.
