# 29단계: IHC 모델에 주어진 입력과 예측 구분

상태: **2026-11-10 (Asia/Seoul) 사용자 입력 조건 해석 확인**. 사용자가 정답 중심을 제공받은 네 클래스 분류이며 자동 검출 성능은 검증하지 않았다고 설명했습니다. 처음 답변의 “48px 영상을 이용” 부분은 Codex 안내 후 표시용 crop과 실제 색상 특징 입력을 구분해 수정했습니다. 다음은 [30단계 분류 오류 해석](STEP_30.md)입니다.

## 처음 제공한 질문

**이 IHC 실험을 “세포 위치를 자동으로 찾아 종류까지 분류한 결과”라고 설명해도 될까요? 입력으로 주어진 정보와 모델이 예측한 것을 구분해 한두 문장으로 설명해 주세요.**

참고할 곳은 영상 위의 **정답 중심점이 입력됩니다** 안내와 오른쪽 **결과·출처 → 전체 테스트의 분류 성능** 아래의 평가 범위 설명입니다. 여기서 ‘중심점’은 세포의 위치이며, 정답 클래스와는 다른 정보입니다.

현재 화면의 네 클래스는 Ki67 양성/음성 종양 세포와 Ki67 양성/음성 비종양 세포입니다. 노란48px 사각형은 표시용 crop 범위입니다. 아래 소스·실험 기록은 참고자료이며 지금 코드를 수정하거나 테스트를 실행하는 과제는 아닙니다.

## 답변 검토와 보완 질문 하나

2026-11-10 (Asia/Seoul) 답변에서 **정답 중심 좌표 제공 → 해당 위치에서 네 클래스 분류 → 자동 검출 성능 미검증**이라는 구분은 확인했습니다.

실제 입력은 중심 주변의 **반경 3px·7px 원형 영역에서 계산한 색상 통계 40개**입니다. RGB, HSV에서 얻은 값과 광학 밀도의 평균·표준편차를 표준화한 뒤 다항 로지스틱 회귀 분류기에 넣습니다. **48×48px crop은 사람이 사례를 살펴보는 화면용 이미지**이며, 이 crop 자체를 분류기 입력으로 전달하지 않습니다. 이 설명은 Codex가 제공한 보완입니다.

**화면용 48×48px crop과 실제 분류기 입력의 차이를 한 문장으로 다시 정리해 주세요.**

사용자 수정 답변:

> 48×48px 영상은 사람이 세포를 확인하기 위한 화면 표시용이며, 실제 분류기는 제공된 정답 중심 좌표 주변의 반경 3px·7px 영역에서 추출한 색상 통계 40개를 표준화한 뒤 로지스틱 회귀로 네 클래스를 예측합니다.

실제 코드·저장 모델과 일치하는 설명으로 확인했습니다. Codex 설명을 받은 뒤 수정한 해석임을 기록하며, 사용자가 모델을 구현하거나 실행한 기여로 기록하지 않습니다.

## Codex 확인 범위

`src/pathology_edge/ihc_baseline.py`에서 `read_points`가 반환한 중심 좌표를 `extract_features(rgb, centers)`에 전달하고 정답 클래스는 별도로 보관하는 흐름을 읽었습니다. 입력 특징을 추출할 때 정답 클래스 값을 특징으로 넣는 코드는 아닙니다.

`dist/ihc/results.json`과 원본 `artifacts/ihc/results.json`의 scope가 일치하고, 중심점 제공·검출/분할 평가 여부가 화면 설명과 같은지 대조했습니다. [28단계의 사례 대조](../artifacts/learning/step28-preparation.json) 입력 해시도 그대로입니다. 이번에 새 특징 추출·모델 추론·학습·브라우저 검사는 실행하지 않았습니다.

후속 검토에서 `extract_features`의 반경·특징 구성, `predict_proba`의 표준화·선형 분류, 화면 예제 내보내기의 48×48px crop 생성을 대조했습니다. 저장된 모델의 특징 이름 40개, 반경 `[3, 7]`, 계수 행렬 4×40 및 공개 모델과 원본 모델의 일치를 확인했습니다. 새 특징 추출·모델 추론·학습·브라우저 검사는 실행하지 않았습니다.

사용자 최초·수정 답변 원문과 받은 도움은 [29단계 검토 기록](../artifacts/learning/step29-review.json)에 남겼습니다. 수정 답변 검토 시 이전 소스·모델·결과 해시 5개도 동일함을 확인했습니다. 원영상 표시나 자동 검출 성능을 확인한 것으로 기록하지 않습니다.
