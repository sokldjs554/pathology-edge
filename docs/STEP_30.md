# 30단계: IHC 네 클래스 중 어떤 구분이 틀렸는지 해석

상태: **사용자 해석 대기**. [29단계](STEP_29.md)에서 화면용 crop과 실제 분류기 입력을 구분했습니다. 이번에는 이미 확인한 첫 실패 사례 하나를 해석합니다. 새 코드·설치·터미널 실행은 없습니다.

## 사례와 질문 하나

[IHC 첫 실패 사례](https://pathology-edge-lab.ykh13571.chatgpt.site/ihc.html?example=incorrect-01)의 영상 아래 **선택 세포의 정답과 예측**을 기준으로 합니다. 사례 ID는 `incorrect-01`, case는 `case_0004`입니다.

- 정답: **Ki67 양성 종양 세포**
- 예측: **Ki67 양성 비종양 세포**

**이 사례에서 틀린 것은 Ki67 양성·음성 구분인가요, 종양·비종양 구분인가요? 두 분류명을 근거로 한 문장으로 설명해 주세요.**

두 분류 표시는 28단계에서 사용자 보고를 받았습니다. 지금은 해당 사례의 해석 하나만 확인하며, 전체 성능이나 다른 사례를 설명하는 과제가 아닙니다.

## Codex 확인 범위

원본 `artifacts/ihc/results.json`과 화면용 `dist/ihc/results.json`의 사례·클래스명이 일치합니다. 원본 이미지 `case_0004_region_0_patch_10_O.png`의 중심 `(179, 98)`에 대응하는 저장 테스트 행이 하나이며 정답 클래스 0, 예측 클래스 2와 확률 벡터가 사례 데이터와 같습니다.

`dist/ihc.js`에서 정답·예측 클래스 ID가 각각 화면의 두 분류명으로 연결되는 코드를 읽고 이전 사례 근거의 입력 해시가 그대로임을 확인했습니다. 새 특징 추출·추론·학습·브라우저 검사는 실행하지 않았습니다. 이 준비는 사용자의 오류 해석 완료를 의미하지 않습니다.
