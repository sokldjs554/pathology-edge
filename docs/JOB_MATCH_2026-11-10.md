## 남은 보완의 우선순위

### 1. C++ 측정·범위 해석 — 완료한 범위

새 대규모 기능을 만들기보다 기존 패치 추출기의 Python/C++ 출력 일치와 스레드별 비용을 직접 확인하는 작업입니다.

- 확인한 범위: 본인 환경의8조건 실행·성공 요약·비교표·CPU 정보와 전체 추론 속도로 확대할 수 없다는 해석을 받았습니다. 원시9회·소스/바이너리 해시 파일에 직접 접근한 것은 아닙니다.
- 이해할 내용: `py::gil_scoped_release`, `std::atomic` 작업 배분, 서로 겹치지 않는 출력 영역, 스레드 생성 비용과 메모리 복사 비용.
- 기존 기록에서 512² C++ 1스레드0.123ms/4스레드0.208ms, 2048²에서는8.400ms/5.299ms입니다. 새 환경이 이 숫자나 순서를 그대로 재현해야 하는 것은 아닙니다.
- [기존 benchmark 스크립트](../scripts/benchmark.py)의 기본 실행은 `artifacts/benchmark.json`을 덮어씁니다. 후속 [별도 실행기](../scripts/benchmark_cpp_review.py)는 새 work 폴더에 기록하며 원본 보존을 확인합니다. [51](STEP_51.md)·[52단계](STEP_52.md)의 사용자 보고 확인을 마쳤고 다음은 [53단계](STEP_53.md)입니다.

### 2. 추가 모델 비교는 하나만 — 선택

| 방향 | 보완되는 점 | 먼저 확인할 조건 |
|---|---|---|
| 작은 ViT/사전학습 모델 대 기존 기준선 | 최신 모델 구현·비교라는 공고 우대와 직접 연결 | 과제·입력 조건을 맞추고 가중치 이용 조건·학습 데이터 중복 가능성·CPU/메모리 예산을 확인. 단순 import나 화면 출력으로 연구 경험을 대신하지 않음 |
| 정답 중심 조건의 작은 CNN 대 IHC 색상 기준선 | 세포 주변 형태 정보와 PyTorch 분류 모델링을 회사의 정량 업무에 연결 | 동일 case 분리, train/validation에서만 선택, macro-F1·종양 양성/음성 오류·양성률 오차·비용 비교. 정답 중심 입력이므로 자동 검출 성능은 여전히 주장하지 않음 |

둘은 대안이며 사용자는 **ViT**를 선택했습니다. 준비와 개발 검증은 C++와 함께 진행했고, 사용자 과제는 C++ 검토 후 ViT 순서로 안내합니다. 새 비교가 기존 모델보다 좋지 않아도 선택 규칙·오류·비용을 정직하게 보고하면 실험 근거가 됩니다.

### 3. 독립 데이터 검증 — 장기 확장

TNBC test는7장·2개 케이스 그룹이고 이미 결과를 상세히 확인했습니다. 3개 seed는 학습 변동을 살펴본 것이며 데이터 독립성을 늘리지 않습니다. 후속 모델 선택은 train/validation에서 하고, 이미 열람한 test 결과를 새 미열람 최종 검증으로 부르지 않습니다. 다른 기관·케이스에 대한 주장을 강화하려면 별도 데이터와 명확한 분리·평가 설계가 필요합니다. 지원 전 필수 추가 기능으로 배정하지 않습니다.
