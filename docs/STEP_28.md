# 28단계: 실제 IHC 실패 사례의 정답·예측 확인

상태: **2026-11-09 사용자 정답·예측 분류 표시 보고 확인**. 사용자가 “구 분류 잘 나와”라고 답했습니다. 문맥상 안내한 두 분류 표시가 나온다는 보고로 기록하며, 원영상·crop의 정상 표시까지 별도로 확인한 것으로 확대하지 않습니다. [원문·범위](../artifacts/learning/step28-review.json). 다음은 [29단계 IHC 입력 조건 해석](STEP_29.md)입니다.

## 직접 열어 볼 사례 하나

[IHC 첫 실패 사례](https://pathology-edge-lab.ykh13571.chatgpt.site/ihc.html?example=incorrect-01)를 엽니다. 상단 **실패 사례**가 선택되고, 영상 제목에 **case_0004**가 표시돼야 합니다. 다른 사례가 열렸다면 실패 사례 목록의 첫 번째를 선택합니다.

영상 아래 **선택 세포의 정답과 예측**에는 다음 내용이 표시됩니다.

- **분류 불일치** · `incorrect-01`
- 정답: **Ki67 양성 종양 세포**
- 예측: **Ki67 양성 비종양 세포**

정답·예측 분류 표시가 나온다는 사용자 보고를 받았습니다. 이 기록은 분류 표시 확인 범위이며, 모델 입력 조건 이해나 모든 화면 요소 검증까지 완료한 것으로 기록하지 않습니다.

## 현재 표시의 근거

이 사례는 `case_0004_region_0_patch_10_O.png`의 정답 중심 `(179, 98)`에서 분류한 저장 결과입니다.224×224 원본 영상과 그 안의 `[155, 74, 203, 122)`인48×48 표시용 crop을 보여 줍니다. 파란 중심은 입력으로 주어진 정답 위치이고 노란 사각형은 표시용 crop 범위입니다.

모델의 선택 클래스 점수는 화면에서50.9%로 표시됩니다. 확률 보정을 하지 않은 점수입니다. 이 단계의 사용자 확인 대상은 영상과 두 분류명이며, 점수 해석이나 입력 조건 이해까지 완료로 기록하지 않습니다.

현재 IHC 실험은 정답 세포 중심점이 주어진 조건의 네 클래스 분류입니다. 앞서 본 TNBC 핵 분할·CMU WSI ROI와 다른 데이터·모델입니다. 자동 세포 검출이나 전체 슬라이드의 임상 Ki67 분석과 구분합니다.

## Codex 확인 범위

표시 사례를 `artifacts/ihc/results.json`과6419개 테스트 예측 중 해당 영상·좌표의 유일한 행에 대조했습니다. 정답·예측·네 클래스 점수와 선택 점수가 일치합니다. 웹용 원본 PNG의 RGB 픽셀 해시가 기록된 원본 픽셀 해시와 같고,48×48 crop이 표시 원본의 해당 영역과 픽셀 단위로 같은지 확인했습니다.

첫 감사에서 원본 파일의 `source_sha256`를 웹용으로 다시 저장한 PNG의 바이트 해시와 잘못 비교해 실패했습니다. 내보내기 코드의 RGB 재저장과 해시 정의를 확인해 원본 바이트 해시와 디코딩 픽셀 해시를 구분했습니다. 결과 파일이나 영상은 변경하지 않았으며, 진단 내용은 아래 근거에 남겼습니다.

준비 당시 화면의 초기 사례 선택·분류 표시 코드와 기존 IHC 브라우저 검사 정의를 읽었습니다. 이후 사용자 보고를 분류 표시 범위로 기록하고 이전 근거의 원본 해시가 같은지 확인했습니다. 이번에 원 데이터셋을 다시 읽거나 새 브라우저 검사·모델 추론·학습·주석 검증을 실행하지 않았습니다.
