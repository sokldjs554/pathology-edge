# 22단계: 실제 WSI에서 R1 분석 영역으로 이동

상태: **사용자 화면 확인 대기**. 21단계의 NMS 대응과 정답 구분 설명을 확인했습니다. 앞서 실제 WSI 화면이 잘 보인다는 보고는 받았으며, 이번에는 저장된 관심 영역으로 이동하는 동작 하나를 확인합니다.

## 직접 할 조작 하나

[실제 WSI 탐색](https://pathology-edge-lab.ykh13571.chatgpt.site/wsi.html)을 열고 왼쪽 **저장된 분석 ROI → R1**을 누릅니다. ROI는 관심 영역입니다. 목록이 안 보이면 위쪽 **영역 목록** 버튼을 누릅니다.

예상 결과는 전체 슬라이드에서 R1 조직 영역으로 확대·이동하고 **A/B 경계 비교** 모드에서 양쪽에 같은 조직 위치가 보이는 것입니다. 오버레이는 방식별 예측이므로 색칠된 모양까지 같아야 하는 것은 아닙니다. 오른쪽 **결과·출처** 제목은 **R1 · 분석한 관심 영역**으로 바뀝니다. 패널이 닫혀 있다면 상단 **결과·출처** 버튼으로 엽니다.

**R1을 누르면 해당 영역으로 확대·이동하고, 양쪽에 같은 조직 위치가 보이는지** 알려 주세요. 이번에는 ‘차이가 큰 경계’나 ‘중복 출처’까지 누를 필요가 없습니다. 작은 화면에서 한쪽 영상만 보이면 그 상태를 알려 주세요.

## 좌표와 분석 범위 참고

R1은 원본 level-0 좌표 `x 5888–6912, y 20608–21632`의1024×1024 영역입니다. 끝 좌표는 제외하며, 중심은 `(6400, 21120)`입니다. 기존 TNBC512×512 정답 실험과 별도의 실제 CMU-1 슬라이드입니다.

전체46000×32893 슬라이드는 확대 탐색할 수 있지만 모델 결과는 사전 선택한3개 ROI에만 있습니다. 이 WSI에는 핵 정답이 없으므로 예측 차이를 Dice 개선으로 해석하지 않습니다. R1 버튼은 저장 결과를 여는 기능이며 새 추론을 실행하지 않습니다.

## Codex 확인 범위

`dist/wsi.json`과 저장 R1 PNG의 해시·크기를 대조했습니다. 사용자가 작성한 `local_to_level0`를 Codex가 별도 호출해 native 좌표의 두 모서리와 중심을 검산했습니다. 이는 독립 감사이며 JavaScript 뷰어가 해당 Python 함수를 호출한다는 뜻은 아닙니다.

`dist/wsi.js::selectROI`가 R1 선택·결과 표시·ROI 맞춤·양쪽 동기화를 연결하는지 읽고, 기존 `web-tests/wsi.spec.js`의 관련 검사 정의도 확인했습니다. 이번에는 새 브라우저 검사·WSI 원본 재추출·모델 추론을 실행하지 않았습니다. 사용자의 화면 확인은 답변 후 기록합니다.
