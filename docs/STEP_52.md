# 52단계: 추출 속도와 전체 추론 속도 구분

상태: **사용자 해석 확인 완료**. [51단계](STEP_51.md)의8조건 실행·비교표 제출에 이어,1.96배는 추출 구간의 결과이고 모델 순전파·확률 결합·후처리가 제외돼 전체 추론으로 확대할 수 없다는 답변을 확인했습니다. [답변·확인 기록](../artifacts/learning/step52-review.json). 다음 사용자 과제는 [53단계 CNN–ViT 비교 실행](STEP_53.md)입니다. 면접 문장 작성은 계속 보류합니다.

## 제출 수치에서 확인한 사실

| 입력 | 가장 빠른 조건 | 중앙값 | Python 대비 |
|---|---|---:|---:|
| 512×512 | C++ 1스레드 | 0.265ms | 1.92배 |
| 2048×2048 | C++ 4스레드 | 11.453ms | 1.96배 |

512²에서 C++ 2·4스레드는 각각0.844·1.071ms로, Python0.509ms보다 느렸습니다. 2048²에서는 C++ 4스레드가1스레드12.425ms보다 약7.8% 짧게 걸렸고,2스레드13.594ms는1스레드보다 느렸습니다. 표시된 반올림 값으로 계산한 근사치입니다.

보고된 logical CPU와 affinity는2개이며 cpuset은0–1입니다. CPU 이름의 “64-Core”는 이 Codespaces에64개 코어가 할당됐다는 뜻이 아닙니다. `cpu.max: max 100000`은 해당 cgroup의 시간 quota가 제한되지 않았다는 표시이며 cpuset/affinity의2개 CPU 범위를 늘리지 않습니다.

작은 작업에서는 매 호출의 스레드 생성·join과 작업 배분 비용이 이득을 넘을 수 있고,2개 CPU에서4스레드를 사용하면 스케줄링 비용도 생길 수 있습니다. 이번 요약만으로 원인별 비중을 확정하거나 반복 실행에서도 같은 순서라고 단정하지 않습니다. RSS는 전체 프로세스 최대값이며 비교용 배열도 포함합니다. 수치가 비슷하다는 이유로 추출기만의 메모리 사용이 같다고 해석하지 않습니다.

## 완료한 질문

**2048²에서 C++ 4스레드가 Python보다1.96배 빨랐으므로, 전체 모델 추론도1.96배 빨라졌다고 설명해도 될까요? 측정한 구간을 근거로 한 문장으로 설명해 주세요.**

실제 측정 코드는 [`measure_case`](../scripts/benchmark_cpp_review.py)의 `extract` 호출 전후입니다. 범위는 [51단계의 측정 조건](STEP_51.md)에 있습니다. 사용자 답변이 이 측정 범위와 일치함을 확인했습니다. 전체 추론 속도를 새로 측정하거나 C++ 전체 구현을 직접 검토한 기록으로 확대하지 않습니다.

ViT 비교 구현·참고 학습·검증과 격리 실행 준비를 마쳤습니다. [53단계](STEP_53.md)의 사용자 실행을 안내했으며 결과를 받기 전까지 완료로 기록하지 않습니다.
