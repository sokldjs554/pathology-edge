# 협업 경험과 본인 판단의 근거

이 문서는 지원자가 설명할 수 있는 사실을 정리한 초안이다. 공고의 ‘GitHub, Jira 등 개발 협업 도구 사용 경험’과 ‘실험 관리 및 개발 협업’에 연결한다. **본인·동기의 역할과 Notebook·오류 메시지를 공유한 사실은 본인이 확인했다.** [확인 질문과 응답](USER_REVIEW_20261118.md). 새 협업 실무나 대회 자료의 독립 검증을 수행한 것은 아니며, 아래 전체 문단의 최종 표현을 승인한 것으로 확대하지 않는다.

설명 초안:

이 경험은 Git 기반 변경·근거 관리의 증거다. 다인 조직에서의 코드리뷰·충돌 조정·Jira 운영을 수행했다는 증거로 확대하지 않는다. 기술적으로 조사하거나 구현한 주체와 실제 명령을 실행한 주체도 구분한다.

## 2. Name That LLM 2인 협업 — 사용자 설명 기준

사용자가 제공한 내용은 다음과 같다. 대회 저장소·Notebook·제출 이력을 이번 작업에서 별도 대조한 것은 아니다.

| 항목 | 사용자가 설명한 사실 |
|---|---|
| 시점·구성 | 2026년 10월, 대학 동기와 2인 팀으로 참여 |
| 본인 역할 | 자료 조사, 코드 작성, 실행, 제출 |
| 동기 역할 | 오류 해결과 개선 방향 검토 지원 |
| 문제·공유 | 추가 데이터의 파일 연결·버전 문제로 실행 중단. Notebook과 오류 메시지 공유 |
| 대응 | 본인은 파일 구성을 확인해 코드 수정. 동기는 연결·버전 확인 방법 함께 검토 |
| 결과 | 이후 모델 구성·데이터 활용 방식을 변경하며 공개 점수 0.333→0.381 |
| 지원 도구 | AI를 코드 작성·수정에 활용 |

협업 문단 초안:

> 2026년 10월 대학 동기와 2인 팀으로 Name That LLM에 참여했습니다. 저는 자료 조사·코드 작성·실행·제출을 맡고, 동기는 오류 해결과 개선 방향 검토를 지원했습니다. 추가 데이터의 파일 연결과 버전 문제로 실행이 중단됐을 때 Notebook과 오류 메시지를 공유했습니다. 저는 파일 구성을 확인해 코드를 수정했고, 동기는 연결·버전 확인 방법을 함께 검토했습니다. AI도 코드 작성과 수정에 활용했습니다. 이후 모델 구성과 데이터 활용 방식을 바꾸며 공개 점수를 0.333에서 0.381로 높였습니다.

파일 연결 수정 하나가 점수 상승 전체를 만들었다고 단정하지 않는다. 공개 점수의 평가 지표 이름·최종 순위·비공개 점수는 추가 확인 없이 채우지 않는다. 대회에서 PR이나 Jira를 사용했다고 덧붙이지 않는다.

## 본인 판단을 설명할 때

문제 → 공유한 정보 → 각자 한 일 → 검증 결과의 순서로 설명한다. 연구 사례에서는 비교 조건 → 실제 결과 → 채택/보류 이유를 연결한다. 예를 들어 내부 Dice 상승에도 외부 악화가 있어 보정 효과의 일반화를 주장하지 않은 해석은 [기존 검토 기록](CONTRIBUTIONS.md)과 연결할 수 있다. 설계·자동 실행을 모두 혼자 수행했다고 바꾸지 않는다.

역할 분담·정보 공유 사실에 대한 확인 질문에 본인이 “응 맞아”라고 답했다. 기존 공개 점수·시점 등은 앞서 제공한 진술을 유지하며 이번 짧은 응답을 모든 수치의 재검증으로 확대하지 않는다. 협업 설명을 위한 사실관계 확인을 마쳤으며 새 대회·협업 과제를 추가하지 않는다.
